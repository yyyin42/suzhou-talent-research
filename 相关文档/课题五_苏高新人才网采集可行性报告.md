# 苏高新人才网（sndhr.com）自动采集可行性报告

> 实测时间：2026 年 9 月 29 日 23:00–23:10
> 实测人：小满（AI 助手）／ 供苏链智绘队使用
> 结论先行：**可以自动采集，已实测跑通并产出可用 Excel。**

---

## 一、结论（三句话）

1. **技术可行**：站点已全站改版为前端框架（Vue）应用，页面文字抓不到，但它的**后台数据接口是公开的**——不需要账号、不需要验证码、不需要破解，用普通脚本就能把岗位列表和岗位描述原文完整取回。
2. **已跑通**：实测拉到全站在挂岗位 **255 条（去重后）**，其中匹配六类岗位族的 **115 条**；抽样拉取岗位详情，**岗位描述原文可完整获取**。
3. **量级要认清**：这是**当前在挂岗位的快照**，255 条不是 600–1000 条。要靠**每周采一期、累积去重**，并叠加其他渠道，才能达到课题目标量。同时描述质量分化严重（见第五部分），这是比"能不能采"更需要注意的问题。

配套已产出可直接使用的采集脚本：`数智调研大赛/工具/sndhr_collect.py`。

## 二、站点技术结构（为什么以前手工复制那么费劲）

| 项目 | 情况 |
| --- | --- |
| 站点性质 | 苏州高新区官方人才网（区人社部门运营），公共就业服务平台 |
| 前端 | Vue 单页应用（SPA），页面内容全由 JavaScript 动态渲染 |
| 后果 | 用浏览器"另存网页"或普通抓取工具**只能拿到空壳 HTML**，拿不到岗位文字 |
| 老版页面 | 全部失效——测试 3 个老网址（`/aspx/jobs/Company` 等）均跳转回应用外壳 |
| robots.txt | **不存在**（访问该路径返回的是首页，说明站点未发布抓取规则） |
| 后台 | Spring Boot 接口服务，独立域名 `apiweb.sndhr.com`，路径前缀 `/web-api` |

**接口是怎么找到的**：从前端 JavaScript 代码里读出接口调用（前端代码公开可见，属正常技术分析，非破解）。

## 三、可用接口清单（实测确认）

### 接口 1：岗位列表（核心）

```
POST https://apiweb.sndhr.com/web-api/find-job/page-advanced
请求头： token: <任意值，空值即可>   Content-Type: application/json
请求体： {"page": 1, "pageSize": 50}
```

**关键坑（实测踩出来的）**：请求头里**必须带 `token` 字段**，哪怕值是空的或写 `null`。不带这个头会返回 `403 拒绝访问，没有权限`——看起来像"需要登录"，其实只是缺个头。这是最容易被误判成"封了爬虫"的地方。

**分页字段是 `page`**（不是 pageNum / current / pageNo，这几个传进去都被忽略，永远返回第一页）。

返回字段（32 个，节选实用的）：

| 字段 | 含义 | 例 |
| --- | --- | --- |
| id / code | 岗位唯一标识 / 岗位编号 | 2090642604798013441 / J2026082100016 |
| name | 岗位名称 | 作业员 |
| enterpriseName / enterpriseId | 企业名称 / 企业标识 | 苏州茂立光电科技有限公司 / 748 |
| salaryFrom / salaryTo | 薪资区间 | 5k / 7k（另有数值版 salaryFromValue） |
| educationDegree | 学历要求（码值） | bachelor |
| workExperience | 经验要求（码值） | oneToThree |
| workNature | 工作性质 | fullTime |
| nature / industry / enterpriseSize | 企业性质 / 行业码 / 企业规模 | 日资 / 1008 / less499 |
| area / address | 区域码 / 详细地址 | 320505 / 苏州新区嵩山路468号 |
| headCount | 招聘人数 | 30 |
| startDate / refreshDate | 发布日期 / 刷新日期 | 2026-08-21 / 2026-09-29 |
| targetList | 福利标签数组 | ["五险一金","绩效奖金",...] |

### 接口 2：岗位详情（拿"岗位描述原文"的关键）

```
GET https://apiweb.sndhr.com/web-api/find-job/job-detail?id=<岗位id>&isPersonal=true
```

返回的 `data.job.description` 就是**岗位职责 + 任职要求 + 薪资福利的完整原文**——这正是 LLM 技能提取要的原料。参数 `isPersonal=true` 不能少，缺了会报参数错误。

### 接口 3：首页热门数据（辅助，可选）

- `GET /web-api/homepage-talent/hot-jobs` → 首页推荐岗位 12 条
- `GET /web-api/homepage-talent/hot-enterprises` → 首页推荐企业
- `GET /web-api/find-job/get-top-enterprise` → 头部企业

## 四、实测数据规模（2026-09-29 快照）

| 指标 | 结果 |
| --- | --- |
| 全站在挂岗位 | **255 条**（6 页 × 50，末页 5 条；id 无重复） |
| 匹配六类岗位族 | **115 条**（按岗位名称关键词初筛） |
| ├ 软件开发 | 32 条 |
| ├ 智能制造 | 51 条 |
| ├ 数字营销 | 21 条 |
| ├ 人工智能 | 8 条 |
| ├ 产品运营 | 8 条 |
| └ 数据分析 | 1 条 |
| 学历分布 | 本科 118、硕士 54、大专 25、不限 24、初中 12、技校 9、博士 5、高中 5、职高 2、小学 1 |
| 经验分布 | **不限经验 196 条（77%）**、1-3 年 35、3-5 年 16、5-10 年 3、10 年以上 1 |
| 工作性质 | 全职 254、实习 1 |

**两个可以直接写进报告的发现**：

1. **经验要求"不限"占 77%**——这个平台的岗位以应届生/无经验友好型为主，与你们"高校人才培养匹配"的主题高度契合，是个很好的切入点。
2. **学历以本科（118）和硕士（54）为主，合计 67%**——说明区内数智类企业招人门槛不低，"高校培养与企业需求错位"这个命题在这个平台上是有数据支撑的。
3. **数据分析岗只有 1 条、人工智能 8 条**——说明这个官方平台**偏制造业与工程技术岗，互联网/数字原生岗位少**。这是必须写进"研究局限"的样本结构偏差，也是需要 24365 平台等其他渠道补位的原因。

## 五、最重要的限制：描述质量分化严重

抽样 8 条详情，描述字数分布：

| 描述字数 | 条件 | 能否做技能提取 |
| --- | --- | --- |
| 300–500 字 | 职责+要求+福利齐全 | ✅ 优质样本 |
| 100–300 字 | 有任职要求段 | ✅ 可用 |
| 20–100 字 | 只有一两句要求 | ⚠️ 勉强，需标注 |
| **< 20 字** | 例："计算机、通信、电子信息等相关专业"（17字）；"（3字）" | ❌ **无法提取技能词** |

抽样 8 条中 **5 条有实质描述**（>20字）。这意味着：

- **原始采集量 ≠ 可用样本量**。255 条里真正能做技能分析的，估计在 100–150 条区间；
- 脚本已自动加上**「描述字数」列**，你们可以按这一列设阈值（建议 ≥50 字才算有效分析样本），把极简岗位单列出来，在报告里说明"剔除极简岗位 X 条"，这是规范做法，不是丢数据；
- 极简岗位本身也是发现——**说明大量中小企业不会规范撰写岗位说明**，这恰恰是"岗位能力信息不透明"的证据，可以作为报告里一个有意思的观察点。

## 六、合规边界（写进报告方法部分）

1. **只访问未登录访客可见的公开接口**，不做登录、验证码、反爬绕过——本次实测全程未触发任何限制；
2. **请求间隔 ≥2 秒**（脚本默认值）；全站 255 条全量采集约 6 分钟、不到 300 次请求，对服务器压力极小；
3. **站点未发布 robots.txt**，即无明确禁止条款；采集行为克制、用于学术研究；
4. 只采集岗位与企业公开信息，**不采集岗位中的联系电话/邮箱等个人联系信息**，不针对单个企业做评价；
5. **仍建议在下次与吴越老师沟通时口头报备**这句："苏高新人才网是区属公共服务平台，我们按其公共服务定位做了有限度采集，间隔 2 秒、不使用登录态、不采集联系方式"——一句话把合规姿态说清楚。

## 七、使用方法（交给张庆阳）

脚本位置：`数智调研大赛/工具/sndhr_collect.py`

```bash
# 第 1 步：试跑 5 条，确认输出正常（约 15 秒）
python sndhr_collect.py --limit 5

# 第 2 步：全量采集（列表 + 详情，约 6 分钟）
python sndhr_collect.py --out 企业端岗位样本_苏高新人才网_20261005_v01.xlsx

# 可选参数
--delay 3        每次请求间隔 3 秒（更保守）
--no-detail      只采列表不采详情（快，但无描述原文）
--page-size 50   每页条数
```

**输出**：Excel 两个工作表
- 「岗位原始表」——21 列，已对齐团队底表结构（岗位编号自动生成 GQ0001 起、来源平台、来源网址、学历/经验/薪资/企业性质/规模已翻译成中文、岗位描述原文、"描述字数"质量列）；「采集人」列留空，由采集者本人填写；
- 「原始字段留档」——保存未经翻译的原始码值与 id，用于交叉复核（对应计划书"每条数据可回溯"的要求）。

**建议采集节奏**：每周一采一期，文件名带日期（`..._20261005_v01.xlsx`），4 期后在合并表里按 id 去重——这样 4 周能累积约 400–600 条不重复岗位。

## 八、对课题整体数据策略的影响（更新采集指南）

| 渠道 | 原定角色 | 实测后调整 |
| --- | --- | --- |
| 苏高新人才网 | 主力 30–40% | **确认为主力**（且已全自动化，不再是人工负担）；预期贡献 300–500 条（多期累积去重后） |
| 国家 24365 平台 | 15–20% | **建议提升**——补官方平台缺失的互联网/数字原生岗位（数据分析仅 1 条就是缺口证据） |
| 企业官网 + 人工抽样 | 20–30% | 保持，作为岗位族均衡的调节手段 |
| CnOpenData | 窄门 | 不变（老师直申试用 + 院系自购排查） |

**一句话总结给老师**：我们已经把苏高新人才网的公开接口打通，全域 255 条岗位（含描述原文）可以在 6 分钟内采集入库，每周采一期可以累积；剩下的量由 24365 平台和企业官网补充。

## 九、风险与应对

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 网站改版 | 接口路径或参数变化，脚本报错 | 脚本有明确报错提示；改版后需重新从前端 JS 定位接口（可再找 AI 助手做一次，约 20 分钟） |
| 接口加鉴权 | 返回 401/403 | 停止采集，转人工或换渠道，**不要尝试绕过** |
| 单期样本不足 | 255 条 < 目标 600 | 多期采集 + 其他渠道补位，报告中如实说明样本边界 |
| 描述过简 | 大量岗位无实质描述 | 用「描述字数」列设阈值（≥50 字为有效样本），剔除数量如实披露 |
| 岗位族失衡 | 数据分析仅 1 条 | 用 24365 与企业官网定向补齐，或在报告中合并相近岗位族并说明 |

## 附：技术细节留档（便于复现与答辩说明）

- 岗位前台网址格式：`https://www.sndhr.com/findJob/positionDetail?id=<id>`（已写入 Excel 的"来源网址"列，便于逐条复核）；
