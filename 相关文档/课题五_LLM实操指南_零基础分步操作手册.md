> 面向：4 人团队，全程假设你从没用过大模型做数据。

## 〇、先看懂：LLM 在这个项目里到底干哪几件事

整个企业端数据分析，拆开来只有四个动作，其中三个可以用 LLM 帮忙：

```text
动作①  把招聘网页上的文字搬到 Excel 里          → 人工做（AI 帮不上）
动作②  从每条招聘文本里提取结构化信息            → ★LLM 主战场
        （要什么学历、什么专业、哪些技能词）
动作③  把零散技能词归入能力簇                    → ★LLM 给建议，人拍板
动作④  统计汇总成「岗位族 × 能力簇」矩阵          → Excel 数据透视表
```

**一个重要预期管理**：LLM 不是一键出结果的黑盒子。正确用法是——  
**人先手工做一小批（这批是"标准答案"）→ 让 LLM 照着做剩下的大批量 → 人抽查纠错**。  
先有标准答案，才有资格让机器批量干活。这就是本手册的执行主线。

**总路线图（也是本手册目录）**：

| 步骤    | 干什么                   | 谁负责       |
| ----- | --------------------- | --------- |
| 第 1 步 | 每人注册一个国产大模型网页版        | 全员        |
| 第 2 步 | 建企业端底表 Excel 模板       | 张庆阳       |
| 第 3 步 | 人工编码 30–50 条（造"标准答案"） | 张庆阳 + 梁夏伟 |
| 第 4 步 | 写提取 prompt，网页版小规模试跑   | 梁夏伟       |
| 第 5 步 | 迭代 prompt，修掉四类常见毛病    | 梁夏伟 + 张庆阳 |
| 第 6 步 | 通过采集及模型质量关口后批量处理 | 全员分工      |
| 第 7 步 | 抽查 10%、纠错、重跑          | 张庆阳 + 梁夏伟 |
| 第 8 步 | AI 辅助把技能词归入能力簇        | 梁夏伟 + 陈鑫垚 |
| 第 9 步 | Excel 透视表汇总成矩阵        | 梁夏伟       |

## 第 1 步：每人注册一个国产大模型网页版（全员的入场券）

**【做什么】**  
每人注册一个国产大模型的**网页对话版**（免费），并完成三个小练习，确保会用。

**【事前准备】**  
一个手机号（注册用）。不用科学上网，不用花钱。

**【在哪操作】**  
浏览器（Edge/Chrome 都行）打开：

- 可使用 **DeepSeek** → `chat.deepseek.com`；也可选择团队已可访问的其他网页版模型。功能、价格和额度以使用时的官方说明为准。
- 备选：智谱 GLM → `chatglm.cn`；通义千问 → `tongyi.aliyun.com`

全队选定同一模型与操作方式，并记录模型标识、日期和 prompt。统一工具有助于控制差异，但不能单独保证结果可比；混用不同方式时分别记录并验证。

**【怎么做】**

1. 打开网页 → 注册/登录。
2. 界面就是一个对话框，把文字贴进去、回车，就会收到回复。就这么多。
3. 完成三个练习（每个 2 分钟，练完你就会用了）：
   - **练习 1（学会贴长文本）**：从任意招聘网站复制一条岗位描述，贴进对话框，输入「用三句话概括这条招聘信息」，看它回复。
   - **练习 2（学会追问修正）**：接着输入「只要其中关于技能要求的部份，列成清单」——体会"不满意就接着提要求"，不用重贴原文，它记得上文。
   - **练习 3（学会指定格式）**：输入「把上面的技能要求整理成表格，两列：技能名、重要程度」——体会"你定格式它照做"。

**【怎么算成功】**

- 四个人都能独立完成上面三个练习；
- 每人新开一个对话时知道点哪里（"新建对话"按钮）——**每个岗位要用新对话处理**，混在一个长对话里会让它记串（原因见第 4 步的说明）。

> 顺带记住三个词（后面全用得上）：  
> **提示词（prompt）**：你发给 AI 的完整指令，相当于点菜时跟服务员说的话——说得越清楚，上的菜越对。  
> **幻觉**：AI 一本正经地编造原文里没有的东西，是这个项目最大的敌人。  
> **新对话**：每次点"新建对话"，AI 就失忆重来——处理批量数据时恰恰需要它"失忆"，只专注当前这一条。

## 第 2 步：建企业端底表 Excel 模板（数据的地基）

**【做什么】**  
在 Excel 里建一张表，定死每一列的名字和填法。以后所有数据都往这张表里进。

**【事前准备】**  
一个共享文件夹（建议结构如下，全员统一）：

```text
课题五企业端/
  ├─ 01_原始采集/        ← 招聘文本原文，只进不改
  ├─ 02_底表/           ← 主表放这里
  ├─ 03_工具/           ← prompt 存档、脚本
  └─ 04_过程版本/       ← 清洗、编码的中间版本
```

**【在哪操作】**  
本地 Excel，文件放 `02_底表/`。命名规则：`企业端岗位样本_20261008_v01.xlsx`（内容_日期_版本）。

**【怎么做】**  
建两个工作表（下方标签处右键 → 重命名）：

**表 1「岗位原始表」**，一行 = 一条招聘记录：

| 列名     | 填法                                |
| ------ | --------------------------------- |
| 岗位编号   | 自己编：GQ0001、GQ0002…（永不重复、永不修改）     |
| 来源平台   | BOSS直聘 / 前程无忧 / 智联 / 公共招聘网 / 企业官网 |
| 来源网址   | 复制浏览器地址栏                          |
| 采集日期   | 例 2026-10-05                      |
| 采集人    | 填姓名                               |
| 岗位名称   | 原文照抄                              |
| 企业名称   | 原文照抄                              |
| 工作地点   | 原文照抄                              |
| 岗位描述原文 | **整段复制，不改一个字**（这是后面喂给 AI 的原料）     |
| 是否重复   | 默认空，去重时标记                         |

**表 2「技能提取表」**（第 3 步开始用）：

| 列名    | 填法                               |
| ----- | -------------------------------- |
| 岗位编号  | 对应表 1                            |
| 岗位族   | 人工智能/数据分析/软件开发/智能制造/数字营销/产品运营/其他 |
| 学历要求  | 按数据字典标准化并保留原文；明确不限才填不限，未提及记缺失，高中等类别不得强塞入大专以上档位 |
| 专业要求  | 原文照抄，多个用顿号隔开                     |
| 经验要求  | 例「3-5年」，原文没有就填「未写」               |
| 技能词   | 每个一行（后面讲怎么拆）                     |
| 技能词出处 | 原文里含这个技能词的那句话（截取）                |
| 能力簇   | 第 8 步再填                          |
| 编码人   | 填姓名                              |

**【怎么算成功】**

- 两张表建好，列名和填法与上面完全一致；
- 随机找一条招聘信息试着填一行，全队对"每列填什么"没有分歧；
- 文件在共享文件夹里，四个人都能打开。

## 第 3 步：人工编码 30–50 条（造"标准答案"，最重要的地基）

**【做什么】**  
不碰任何 AI。四个人（至少两人独立）**手工**从 30–50 条真实招聘文本里提取信息、填进表 2。

**为什么要先手工做？** 三个理由：

1. 你自己都不会提取，就没法判断 AI 提取得对不对——这一批就是日后抽查 AI 的**标准答案**；
2. 手工做的时候会自然冒出分歧（"数据分析算不算一个技能词？""'熟悉机器学习'算要还是会？"），这些分歧就是**编码手册**的雏形；
3. 亲身体会一遍有多费时间，你会立刻明白为什么第 6 步要上批量——而不是觉得"反正有 AI 随便跑"。

**【事前准备】**

- 表 1 里已有 30–50 条真实数据（用计划书定的渠道：公共招聘网、平台公开页人工复制，六类岗位各 5–8 条）；
- 一份共享文档「编码手册.docx」，初始只有一句话：**技能词 = 原文明确要求求职者具备的工具、语言、方法；'加分项'里提到的也算；没写的不算**。

**【在哪操作】**  
Excel + 编码手册文档。

**【怎么做】**

1. 张庆阳、梁夏伟**各自独立**填同一批 30–50 条（不许商量）。在用于改 prompt 前划分开发材料与保留测试材料，例如 40 条中 25 条开发、15 条测试；实际数量和覆盖另记。测试材料不进入 few-shot 示例或 prompt 调整。
2. 填完放一起比对：按岗位编号逐条对，重点比分歧点——某技能词你提了他没提、学历他写"本科"你写"不限"。
3. 每个分歧讨论出一条规则，**写进编码手册**。例如：
   - "熟练使用 Office" → 拆成「Office办公软件」一个词，不拆 Excel/Word/PPT；
   - "具备良好的沟通能力" → 算软技能「沟通能力」；
   - "有数据分析经验优先" → 算，「数据分析」标为"加分项而非硬性"。
4. 讨论完后**各自回去按新规则改一遍**自己的表，再比一次。

**【怎么算成功】**

- 保存裁决前两人结果，明确比较字段和单位，再报告一致率；80% 如采用仅作内部试验目标，不把整条多标签记录含混地算作一个判断；
- 编码手册积累出 10 条以上明确规则；
- 这 30–50 条人工结果单独存一份，命名「**标准答案集_v1.xlsx**」——它将伴随整个项目。

> 如主要字段仍有系统性分歧，继续修订规则，不进入批量处理。明确指标、分母及岗位族覆盖后，由团队与老师确认放行标准。

## 第 4 步：写提取 prompt，网页版小规模试跑

**【做什么】**  
把"提取规则"翻译成一份发给 AI 的标准指令（即 prompt），在网页版对话里对 5 条招聘文本试跑。

**【事前准备】**

- 编码手册（第 3 步的成果——prompt 里的规则就是从它来的）；
- 标准答案集（用来对照）。

**【在哪操作】**  
DeepSeek 网页版（第 1 步注册的），外加一个记事本文件存 prompt（存到 `03_工具/prompt_v1.txt`，**prompt 必须存版本**，这是研究留痕的硬要求）。

**【怎么做】**

1. 新建对话，把附录 A 的完整 prompt 复制进去发送（它就是按你们的编码手册写的）。
2. 看它回了一段"收到"之类的话后，**再新建一个对话**，按 prompt 的要求：先贴 prompt，紧接着贴第一条岗位描述原文，发送。
3. 收到一坨花括号包起来的文字——这就是 **JSON**（读作"杰森"）。不用怕，它只是"用固定格式写的表格"：每个引号包住的是列名，冒号后面是内容，机器和 Excel 都好认。

例如输入一条数据分析师招聘，正常应返回类似：

```json
{
  "岗位名称": "数据分析师",
  "岗位族": "数据分析",
  "学历要求": "本科",
  "专业要求": ["统计学", "数学", "计算机相关专业"],
  "经验要求": "1-3年",
  "技术技能词": ["Python", "SQL", "Tableau", "统计分析"],
  "软技能词": ["沟通能力", "报告撰写"],
  "技能词出处": ["熟练使用Python进行数据清洗与分析", "掌握SQL语句", "使用Tableau制作可视化报告", "具备良好的沟通能力"]
}
```

1. 把这 5 条结果复制存下来（建议每个岗位一个 txt，存 `03_工具/试跑结果/`）。

**【怎么算成功】**

- 5 条全部返回**合法**的 JSON（花括号成对、字段一个不少）；
- 和标准答案集逐条对比：技能词大体一致（漏 1–2 个属正常，此时还不要求完美）；
- **没有出现原文里没有的技能词**（幻觉）——出现了就说明 prompt 要改，进入第 5 步。

## 第 5 步：迭代 prompt，修掉四类常见毛病

**【做什么】**  
对照试跑结果和标准答案，把 prompt 改到稳定可靠。这一步是整个 LLM 环节**性价比最高**的一步——prompt 每改好一分，后面几百条全受益。

**【事前准备】**  
试跑的 5–10 条结果 + 标准答案集，逐条并列对比。

**【在哪操作】**  
记事本改 prompt（存 `prompt_v2.txt`），网页版重跑对比。

**【怎么做】**  
按下表"对症下药"，四类毛病基本覆盖 95% 的问题：

| 毛病     | 表现                               | 药方（加进 prompt 的话术）                                    |
| ------ | -------------------------------- | ---------------------------------------------------- |
| ① 幻觉   | 返回了原文没有的词（如原文没提 R 却输出 R）         | 强调「原文没有的信息一律填 null，**禁止根据岗位名推测通常需要的技能**」             |
| ② 漏提   | 原文写了「熟悉 Hive、Spark」，它只提了 Spark   | 加「逐句阅读，技能要求部分每一句都要检查」                                |
| ③ 拆分不当 | 「报表及统计软件开发」拆出「报表开发」「统计软件开发」，或干脆漏 | 加「一个短语包含多项技能时全部拆出」；这类"连体技能"是已知难点，人工抽查重点盯             |
| ④ 格式跑偏 | 有时多一句解释、有时字段顺序变了                 | 强调「严格按 schema 输出，第一个字符就是 {，不要任何前言、解释、markdown 代码块标记」 |

**关键纪律：改一版、存一版，保持分析口径一致。** 不将不同规则的结果未经校正直接拼接。规则改变后重处理受影响范围；若影响全体，则全量重跑。保留时间与费用记录，重跑并非零成本。

**【怎么算成功】**

- 开发材料上检查格式、证据和主要错误后，用未参与改 prompt 的保留测试材料评估 Precision、Recall、F1 及字段错误，分别记录分子、分母与样本范围；
- 小样本未见幻觉不代表总体零幻觉，85% 等阈值如采用仅作待确认的内部目标；
- 保存正式采用的 prompt 版本。规则改动后保留历史结果，对受影响范围重新处理并确保分析口径一致；若根据保留测试结果再调规则，需要补充新的保留测试材料。

## 第 6 步：规模化——通过关口后处理确认范围的记录

**【做什么】**  
用固化好的 prompt，把表 1 中经过纳入与描述质量检查、属于确认范围的记录跑一遍 LLM 提取。

**【事前准备】**

- 表 1 数据采集到位（这一步和采集并行推进，采一批跑一批）；
- prompt_final 已固化；
- 全队开一次 15 分钟会，选定路线 A 或 B（可以混用：先用 A 跑起来，同步搭 B）。

### 路线 A：网页版人工流水线（零代码，零成本）

**在哪操作**：DeepSeek 网页版 + Excel。

**怎么做**：

1. 每人认领 150–250 条（1000 条 ÷ 4 人）。
2. 每条三动作：**新建对话 → 贴 prompt + 贴岗位原文 → 把返回的 JSON 粘到 Excel**。
3. 建议在表 2 加一列「提取方式」填「人工跑」——万一以后和路线 B 混用，可以分开统计。
4. 熟练后一条约 1.5–2 分钟，250 条 ≈ 8 小时，分摊到两周完全可行。

**优点**：今天就能开工，零门槛。  
**缺点**：人肉复制粘贴 200 次难免手滑（漏贴、粘错行），第 7 步抽查就是兜底。

### 路线 B：API + 脚本批量跑（需要一点点设置，一劳永逸）

先解释两个词：

- **API**（读"埃皮艾"）：相当于外卖窗口——不去餐厅坐着吃，而是让程序自动"下单"问 AI。可以通过程序调用模型，但模型、参数、上下文和产品配置可能与网页版不同，需要单独验证。
- **API key**：一串字符，相当于取餐凭证，证明"下单的是你、从你账上扣钱"。

**在哪操作**：团队选定的模型开放平台。先确认模型、接口、使用条件和预算，用 10 条试跑的输入输出用量估算费用，计入重试与重跑；不预先保证 10 元覆盖全项目。

**怎么做**（梁夏伟主责，张庆阳陪跑）：

1. 确认开放平台和预算 → 创建 API key → 用环境变量等安全方式保存，绝不提交仓库、发群或出现在截图中。
2. 附录 B 有一个现成脚本 `batch_extract.py`（找你们的 AI 助手照抄即可，不用自己写）。它做的事：读 Excel 里所有岗位原文 → 逐条发给 AI → 把返回的 JSON 拆开写回另一张表。整个过程相当于路线 A 的机器人版。
3. 在电脑上装好 Python 环境运行（让 AI 助手带着装，一次配好）。
4. 先拿 10 条试跑（脚本里有 `--limit 10` 参数），确认输出正常，再跑全量。
5. 跑完得到一张「LLM提取结果表」。

**【怎么算成功】（两条路线通用）**

- 表 1 里每一条岗位编号在「LLM 提取结果表」里都有对应结果，一条不缺（缺的就是脚本没跑到的，补跑）；
- 结果表里 JSON 全部合法、字段齐全；
- 「提取方式」列如实记录了每人/每批的来源；
- 路线 B 记录实际用量、费用和失败条数，符合团队确认的预算。

## 第 7 步：随机抽查、困难样本检查与人工修正

**【做什么】**
从正式结果中随机抽查，例如 600 条抽 60 条；另选困难样本检查，分别记录。10% 是可讨论的抽样比例，不是质量证明。保留人工最终复核。

**【怎么做】**

1. 从明确的正式结果总体中抽样。用 `RAND()` 时将随机数粘贴为值，保存总体版本及入选编号；开发标准答案不能自动加入随机样本。
2. 对照原文，按统一规则建立或核对人工参考答案，检查漏提、无依据内容、拆分、要求程度和格式。
3. Precision=正确项/提取项，Recall=正确项/参考项，F1=2PR/(P+R)。幻觉等错误另列类型及分母，字段准确率单列。
4. 个别错误人工修正并标记；系统性错误修订规则并重处理受影响范围，保持最终分析版本口径一致。原始模型响应、人工修改与重跑版本分别保存。
5. 分别报告随机样本、困难样本、保留测试的结果，以及修正前性能和修正过程，不能用修正后的指标冒充模型原始性能。

**【怎么算成功】**

- 抽查入选编号、检查人、证据、错误、修正和版本可回溯；
- 指标有明确分子、分母和样本范围，不将 2%、10% 等未论证阈值写成通用标准；
- 主要系统性错误已处理，团队及老师认可后进入最终统计。

## 第 8 步：AI 辅助把技能词归入能力簇（人拍板，AI 只建议）

**【做什么】**  
把结果表里几百个零散技能词（Python、SQL、沟通能力、需求分析……）归到计划书定的能力簇里（技术与工程实现 / 数据处理与分析 / 业务与产业理解 / 数字工具与运营 / 项目实践 / 协作沟通）。

**【事前准备】**  
能力簇框架 + 每簇的技能词示例（计划书模块 D 那张表）。

**【在哪操作】**  
网页版对话即可，不用写脚本。

**【怎么做】**

1. 一次性把「能力簇定义 + 全部技能词清单」贴给 AI，要求它**只输出一张两列对应表：技能词 → 建议能力簇 + 一句理由**。
2. 两人（梁夏伟 + 陈鑫垚）独立过一遍 AI 的建议表，每行三种裁决：同意 / 改簇 / 说不清。
3. "说不清"的词（通常 10–20 个）开会定，定完的规则**补进编码手册**——它正在长成你们自己的方法论。
4. 特别当心两类 AI 拿不准的词：「数据分析」（工具技能还是业务能力？）、「产品思维」（业务簇还是运营簇？）——这类边界词值得在报告里专门写一段"我们如何界定"，恰恰体现研究深度。

**【怎么算成功】**

- 结果表「能力簇」列全部填完，没有一个空格；
- 每个技能词的归类都能给出一句理由（报告答辩时被追问"这个为什么归业务簇"要答得上来）；
- 编码手册更新到含能力簇规则的版本。

## 第 9 步：按不重复记录生成出现率矩阵

**【做什么】**
形成“岗位族 × 能力簇”的企业端提及比例表，与学生端并列解释。

**【怎么做】**

1. 筛选去重、纳入且描述合格的记录，锁定分析版本及要求/优先的纳入规则。
2. 从技能明细得到唯一“岗位编号 × 能力簇”组合。同一记录有多项同簇技能，该簇只计一次。
3. 按岗位族和能力簇汇总不同岗位记录数；分母另从合格岗位表统计。出现率=该簇不同记录数/该岗位族合格记录数。
4. 不使用技能明细行的“占总计百分比”代替上述分母。岗位族采用多标签时，分类间可能重叠，另披露规则。
5. 手工复算至少三个格子，图表标注样本数、时间窗、来源与口径；不合格描述的数量另报。

**【怎么算成功】**

- 每个格子可回溯到记录编号及证据；
- 手工复算一致；
- 企业提及比例与学生自评不直接相减为真实能力缺口，探索性指数须经方法确认。
