> 项目：苏州数智产业岗位技能需求与高校人才培养匹配调研  
> 团队：苏链智绘队（南京大学数字经济与管理学院）  
> 版本：v1.0 · 2026 年 10 月 8 日  
> 适用对象：有基础表格操作经验、尚无完整调研经验的四人团队

## 一、使用方法与学习目标

采用“学一组知识—做一个练习—交一份成果—由另一人复核”的方式。全员掌握研究设计、人工编码、问卷和统计解释，张庆阳、梁夏伟进一步学习 Python 和模型调用。用同一批真实岗位贯穿课程，减少重复准备。

读完并完成练习后，每个人应能独立完成：

1. 解释研究对象、样本边界和一个变量的测量方式。
2. 按同一手册编码一条岗位，并为判断找到原文证据。
3. 指出模型提取中的漏提、无依据提取和错分。
4. 从底表复算一个统计数，并解释其分母。
5. 把企业能力项对应到学生问卷，再解释比较的限制。
6. 用三分钟讲清一条发现的证据、可能解释和建议。

## 三、第 1 课：研究设计——把问题变成变量

**要理解什么**

“企业需要什么、学生具备什么”需要拆成可测量的能力项。这叫操作化。不要直接让企业端与学生端都回答一个含混的“数字能力”。

| 能力项 | 企业端证据 | 学生端测量 |
| --- | --- | --- |
| 数据清洗 | 明确要求清洗、整理数据 | 能否处理缺失值、重复记录、格式错误 |
| SQL 查询 | 明确要求 SQL；区分要求与优先 | 能否独立完成筛选、汇总、关联查询 |
| 项目实践 | 要求或优先相关项目、实习 | 有无经历、承担任务、完成成果 |
| 沟通表达 | 汇报、需求沟通、跨部门协作 | 是否完成过对应任务及自评水平 |

区分三种判断：描述样本中 SQL 的提及比例；比较不同岗位族的比例；判断某课程是否导致能力提高。当前项目主要做描述和比较。实习学生自评分较高，还可能与专业、年级、主动性等因素有关，不能直接归因于实习。

**练习与交付**：每人把一个问题填成“研究对象—变量—来源—计算方式—可回答的问题”，合并成研究设计表。

**验收**：每个拟收集字段都有明确用途；能区分描述、比较与因果。

## 四、第 2 课：抽样与边界——确定结论适用于谁

**要理解什么**

- 总体：希望了解的全部对象。
- 样本：实际取得的对象。
- 抽样框：从哪些平台、地域、岗位族和时间窗选取对象。
- 分析单位：在数招聘记录、企业、学生，还是技能。

一条广告可能招多人，同一工作也可能重复发布。因此报告中的记录数不是实际职位空缺数。在线招聘还有平台覆盖偏差和选择性披露：未写 Office 并不能证明不需要 Office。[ONS 招聘数据指南](https://www.ons.gov.uk/employmentandlabourmarket/peopleinwork/employmentandemployeetypes/methodologies/measuringlabourdemandvolumesacrosstheukusingtextkerneldatauserguide)可供学习去重与覆盖边界。

学生问卷如经班级群、熟人转发回收，应报告学校、专业、年级与传播渠道的实际构成。增加条数不能自动消除选择偏差。

**练习与交付**：写明“平台 × 地域 × 岗位族 × 时间窗”，列出可能遗漏的三类企业或学生，形成样本边界说明。

**验收**：能为结论写出适用范围；区分原始量、去重后量、文本合格量、最终纳入量。

## 五、第 3 课：能力框架与人工编码——把判断写成规则

**要理解什么**

岗位族表示工作类型；能力簇表示一组能力；能力项与技能词表示具体能力及文本表达。一条软件开发记录也可以涉及数据分析能力，二者分别编码。

用“能力簇 → 能力项 → 技能词/任务”组织共同框架。六簇初版沿用技术与工程实现、数据处理与分析、业务与产业理解、数字工具与运营、项目实践与问题解决、协作沟通与职业素养。

参考 [O*NET 内容模型](https://www.onetcenter.org/content.html)与 [ESCO 技能分类](https://esco.ec.europa.eu/en/classification/skill-main)，学习职业、任务、知识和技能的区别。保留映射和调整说明，引用这些体系本身并不意味着你们的六簇框架已得到验证。

**教学示例（虚构，不进入真实数据集）**

> 数据运营专员：负责整理业务数据并制作周报，熟悉 Excel 和 SQL；有 Python 使用经验者优先，能够与业务部门沟通需求。

| 项目 | 可记录判断 |
| --- | --- |
| Excel、SQL | 原文明示的技能 |
| Python | 原文明示的优先项，单独保留要求程度 |
| 数据整理、周报、沟通需求 | 保留为任务或能力证据；按手册规定映射 |
| 学历、年限 | 未提及，记缺失，不推测 |
| 岗位族 | 依据完整任务和边界规则复核，不能只看标题 |

编码手册至少规定：技能与任务的边界；要求/优先/否定/培训的区别；未提及/明确不限/待复核的区别；同义词归并；主分类与多标签规则。

“本科及以上”可标准化为最低本科，同时保留原文；“学历不限”才能记不限；没有学历信息记 null 或未提及。原文出现高中等类别时，应保留，不能强塞入大专及以上类别。

**练习与交付**：同一批 10–20 条至少两人独立编码，不预先交换答案。保存各自结果、分歧、裁决及规则版本；后续扩到 30–50 条。

**验收**：至少 10 条带正例和反例的规则；再次出现相同问题时可按规则处理。

## 六、第 4 课：Excel 与数据管理——先确定每行的含义

**要理解什么**

建立相互关联的三张表，而不是把多个技能、证据和裁决都挤在同一单元格。

| 表 | 一行含义 | 主要字段 |
| --- | --- | --- |
| 岗位表 | 一条招聘记录 | 稳定编号、来源、日期、批次、企业、岗位、原文、质量、纳入状态 |
| 技能证据表 | 某条记录中的一项技能证据 | 岗位编号、原文词、标准词、证据句、要求程度、编码人、复核状态 |
| 技能映射表 | 一项技能与能力项的映射 | 标准词、同义词、能力项、能力簇、规则版本 |

编号排序后不变，用于连接各表。原始材料、清洗数据、人工裁决分别留版本；无关联系方式入库前去除，来源和必要证据仍保留。筛选去重只作用于分析副本，原始记录保留重复状态及理由。

全员练习筛选、冻结表头、数据验证、条件格式、COUNTIFS、查找匹配、缺失检查和透视表。

**核心计算规则**

设某岗位族有 20 条去重、纳入且描述合格的记录，8 条提到 SQL，则 SQL 出现率为 8/20=40%。同一记录重复提到 SQL 只计一次。统计能力簇时，一条记录包含簇内五项技能，该簇也只计一次。

先生成唯一“岗位编号—能力项/能力簇”组合，再汇总；分母为对应岗位族的合格记录数，不是技能行数或全部岗位总数。只纳入能力证据的要求、优先等取值应事先锁定；如分开统计，分别标明口径。描述不合格记录的数量单独披露。

**练习与交付**：小样本缺失表、重复标记、质量表和出现率表。

**验收**：三个格子从原文手工复算一致。若一个簇率超过 100%，先检查是否按技能行重复计数。

## 七、第 5 课：Python 与公开数据获取——读懂已有工具

**学习顺序**

| 内容 | 为什么学 |
| --- | --- |
| 文件路径、变量、字符串、列表、字典 | 理解输入文件和单条记录结构 |
| 条件、循环、函数 | 批量检查、重复执行规则 |
| CSV、XLSX、JSON | 读取表格、保存模型结果 |
| pandas | 筛选、去重、连接、分组统计 |
| 日志、异常和结果保存 | 找到失败记录，防止静默漏数据 |

优先学习 `read_excel`、`isna`、`drop_duplicates`、`merge`、`groupby` 和导出；可用 [pandas 官方入门教程](https://pandas.pydata.org/docs/getting_started/intro_tutorials/)。本课先实现表格自动处理，SQL 编程不列为必修；SQL 作为技能词时要理解其任务含义。

公开数据部分理解：网页与接口的区别、分页、列表与详情、请求状态、限速和停止条件。50 条列表标题不等于 50 条完整描述，每页可访问也不等于各页无重复。

阅读现有采集框架的配置、输入、输出和日志。先离线自测，再按项目允许范围小规模试跑。`dry-run` 只是试运行方式，本身不保证请求量小；试跑前核对 `limit` 或 `max_pages`。商业平台不做自动抓取；公开来源遇 401/403/429、验证码或访问限制立即停止，不绕过。

**练习与交付**：对已有本地小样本用 Python 重做 Excel 的行数、缺失、去重和出现率统计，保存输入、规则与日志。

**验收**：两种方式结果相同；另一人可以按说明运行，不依赖作者现场操作。

## 八、第 6 课：LLM 提取——把规则写成可检查的指令

**要理解什么**

Prompt 包含任务、规则、示例与输出格式；zero-shot 不给示例，few-shot 给少量正确示例；JSON 表达数据，schema 规定字段、类型与允许值。JSON 合法只代表结构可读取，不代表内容正确。

提示词采用“任务—编码规则—字段定义—边界示例—原文—输出要求”。把招聘原文作为数据，原文中的指令不能改变提取规则。词典匹配可以作为另一组候选结果，与模型结果核对；并集仍须复核，不自动当参考答案。

**推荐教学输出结构（虚构示例）**

```json
{
  "岗位族候选": "待复核",
  "学历要求": null,
  "学历状态": "未提及",
  "技能": [
    {
      "原文表达": "有 Python 使用经验者优先",
      "标准技能": "Python",
      "要求程度": "优先",
      "证据句": "有 Python 使用经验者优先"
    }
  ]
}
```

一项技能与证据放在同一对象，避免两个数组错位。无依据的信息不填；否定、优先和培训信息保留；岗位族只是候选。统一 schema 后再入表，不能未经转换混用不同输出版本。

网页版完成初步练习，批量调用前再学 API 请求、凭证、费用估算、结果保存、失败补跑。凭证从环境变量等安全位置读取，不提交 GitHub。保存模型标识、日期、prompt 版本、参数、原始响应、错误和人工修正。模型支持温度参数时，低温度可减少随机性，但不保证结果完全相同；网页版与 API 也不应假定完全一致。

阅读 [BIS 经济学家 LLM 入门](https://www.bis.org/publications/qr-202412/large-language-models-primer-economists)中的工作流程与评估，以及[招聘信息结构化提取论文](https://assets.amazon.science/ea/42/e1e6b73f42dfaf52760cec2ce770/extracting-structured-labor-market-information-from-job-postings-with-generative-ai.pdf)的字段与验证方法。

**练习与交付**：对已人工编码的 5–10 条试跑，记录漏提、无依据提取、拆分与要求程度错误，形成 prompt v0.1 和错误表。

**验收**：每项输出可核对证据；能根据错误改规则。小样本成功后，仍须通过独立测试才能批量处理。

## 九、第 7 课：提取评估与编码一致性——明确分子和分母

**要理解什么**

人工参考答案由独立编码与裁决形成，也要保存版本。先规定技能匹配规则，例如 Python/python 是否相同，数据分析/数据清洗是否不同。

设 TP 为正确提取的项数、FP 为错误提取项数、FN 为遗漏项数：

- 精确率 Precision = TP/(TP+FP)：提出来的有多少正确。
- 召回率 Recall = TP/(TP+FN)：应提取的有多少找到。
- F1 = 2PR/(P+R)：二者的调和平均数。

教学例：参考答案有 10 项技能，模型输出 8 项，正确 6 项。Precision=75%，Recall=60%，F1≈66.7%。FP 既可能是无依据内容，也可能是错分或不符合编码范围，需分别记录。

学历、经验等字段另报准确率和缺失处理错误。分母为零时写“不适用”并说明规则，不随意填 0。分别查看技术技能、软技能和不同岗位族的错误，不只报总体数。

编码一致性先用一致率和分歧类型；岗位族等单项分类可再学 Cohen's kappa：

`κ =（实际一致率 − 随机预期一致率）/（1 − 随机预期一致率）`

计算使用裁决前的独立编码。多标签技能需按明确的岗位—技能判断单元等方案评估，不能把整条多标签记录随意塞进一个单分类指标。

**训练与测试分开**

将 30–50 条参考材料分为开发材料和保留测试材料，例如 40 条中的 25 条用于改 prompt，15 条保留测试。尽量覆盖不同岗位族和困难文本；这些数量仅为练习示例，不能保证统计精度。测试后若再据其改 prompt，该批已成为开发材料，需要补充新的保留测试。

正式结果做随机抽查，同时单列困难样本检查；标准答案开发集不能自动算作随机抽查。全量保留人工最终复核。报告分别说明自动结果的抽查指标、发现的错误及修正过程，不能以修正后的结果冒充模型原始性能。

小样本零幻觉只说明该批未观察到；10% 抽查是比例，不是达标证明。85% 等阈值若采用，应标为内部试验目标，经老师确认；不写成普遍学术标准。

**练习与交付**：技能 P/R/F1 表、字段错误表、裁决前一致性记录、开发与测试划分表。

**验收**：每个指标可复算，样本范围明确，主要系统性错误已有处理方案。

## 十、第 8 课：问卷与访谈——把共同能力变成学生能回答的问题

**要理解什么**

从能力项出发写题。例如企业端编码 SQL 查询，学生端问：面对业务数据表，能否用 SQL 完成筛选和分组汇总？

可试用五级行为量表：1 未接触；2 了解概念；3 能在指导下完成；4 能独立完成常规任务；5 能独立处理较复杂任务。另设“不了解题意/不适用”等选项时，提前规定处理方法，不算作最低能力。

分别问学过的课程、当前任务能力、实践经历和就业方向。一题测一个概念，避免同时问数据处理与沟通。自评是自评，不能直接当客观技能测验。

预试 10–15 人，记录填答时间、困惑题目和选项缺口，并请被试解释理解过程。[Pew 问卷设计指南](https://www.pewresearch.org/writing-survey-questions/)可供学习措辞、选项、顺序与预试。有效问卷剔除规则事先记录，异常快答、逻辑矛盾等先复核，不因结果不符合预期而删除。

访谈先讲清自愿参加、匿名使用和记录方式，录音须征得同意。追问具体经历，例如“最近一次数据项目中负责什么、卡在哪里、课程如何帮助”。分别保留匿名原话、归纳与解释。小规模访谈用于补充机制线索，不以提及次数代替总体比例。

**练习与交付**：“能力项—招聘证据—问卷题—访谈追问”对应表、问卷预试记录、匿名练习访谈纪要。

**验收**：每题有研究用途；被试能正确理解；能力自评、课程和实践分别测量。

## 十一、第 9 课：描述统计与匹配——先理解指标含义

**要理解什么**

先学频数、比例、均值、中位数、分组与缺失。图表标明来源、时间、有效样本数、分母和变量定义；自评分优先报告等级分布与中位数，均值可辅助。子组过小时合并展示或注明仅作案例，不能据少量记录做稳定排名。

企业端“80% 的广告提到 SQL”测量提及比例；学生端“自评平均 3 分”测量自报能力。即使都转成百分制，也没有自动变成同一种量，不能直接宣称有多少真实能力缺口。

**第一版推荐并列呈现**

| 能力项 | 企业端 | 学生端 | 解释材料 |
| --- | --- | --- | --- |
| SQL 查询 | 提及比例；要求/优先比例 | 能力等级分布；相关经历 | 岗位证据、任务案例、访谈 |
| 项目实践 | 要求/优先经历的比例 | 相关经历比例；承担任务 | 课程与项目资料、访谈 |

先确定哪些学生与哪个岗位族对应，如目标就业方向、相关专业、经历；规则预先记录。即使两个比例可以并列，它们也可能指向不同总体，不自动表示逐人匹配或真实短缺。

如需综合差距指数，与老师确认转换、阈值、权重和解释范围，并标明探索性。稳健性检查可包括分开要求与优先、更换权重、按渠道或学生群体比较；报告结果是否稳定，不选择性只呈现有利版本。

技能共现需要学时，按“同一条记录是否同时提到两项技能”统计；出现次数不是因果关系，共现图只在规则与计数核验后制作。

**练习与交付**：并列匹配表；用招聘、问卷、访谈解释三个能力项；记录一种替代计算或分组方案。

**验收**：能说明指标含义、比较依据和不能回答的问题；三个格子可回溯复算。

## 十二、第 10 课：文献、报告与协作——写出证据链

**要理解什么**

每篇文献先回答：研究对象、数据来源、变量构造、验证方法、可借鉴做法。陈鑫垚重点读 [Text as Data](https://www.nber.org/papers/w23276)，其余按模块阅读。具体论点回到原文，核实版本、作者、年份和出处；AI 摘要不能替代文献原文。

主要发现采用：

`发现 → 计算依据 → 原文/访谈证据 → 可能解释 → 适用范围 → 建议`

建议写清对象、行动、实施条件和评价指标。比如实践不足，应进一步说明谁提供什么实践、如何进入课程、用何种成果评价，不能只写“加强校企合作”。

全员学习 GitHub 查看文件、版本差异、分支和提交。提交说明写清改什么、为什么改、如何验证。代码与方法文档可进仓库；问卷明细、访谈原始记录、原始数据按项目权限和存储规则管理，不默认上传公开仓库。稳定岗位编号是主要回溯依据，表格行号仅辅助定位。

**练习与交付**：一页发现卡、文献方法对照表、修改记录、三分钟讲述。

**验收**：另一人能按材料复算并追问；事实、解释和建议明确区分。

## 十五、第一轮练习与最终自查

第一轮可选 10 条允许使用来源的真实岗位，覆盖至少四类岗位族与长短、混合等情况。张庆阳、梁夏伟对全部 10 条独立编码，郑旭晨、陈鑫垚各独立编码其中至少两条并参与裁决。先保留独立结果，再写规则；随后对其中 5 条做 LLM 试跑、手工计算一个技能出现率。该批用于开发练习，后续另选保留测试材料。

最终检查：

- [ ] 全员能解释研究对象、抽样框和分析单位。
- [ ] 小样本有稳定编号、来源、日期及必要原文。
- [ ] 同一批独立编码完成，裁决前结果与分歧留存。
- [ ] 数据字典区分未提及、不限和待复核。
- [ ] prompt、模型、输出与人工修正有版本记录。
- [ ] 开发材料与保留测试材料分开，评估分子分母清楚。
- [ ] 出现率按不重复记录计算，三个格子复算一致。
- [ ] 问卷对应共同能力项，预试完成且留修改理由。
- [ ] 企业提及比例与学生能力等级并列解释，未误称真实缺口。
- [ ] 正式采集与处理满足关口条件，确认意见留档。
- [ ] 主要发现有来源、计算、解释、局限与行动建议。
- [ ] 非作者能重做至少一个模块，并完成三分钟讲述。
