# 课题五假期预备任务清单与学习路线

> 项目：苏州数智产业岗位技能需求与高校人才培养匹配调研
> 团队：苏链智绘队
> 适用阶段：正式项目启动前、指导老师不便及时沟通期间
> 制定日期：2026 年 9 月 30 日

## 一、先说结论

假期期间不需要等待老师，也不建议继续盲目扩大采集量。团队可以独立完成四类准备：

1. **把概念学懂**：知道大模型如何把招聘文本转成可统计变量，以及这种方法的风险。
2. **把数据流程走通**：用少量公开岗位完成“获取—清洗—人工编码—LLM 提取—人工复核—汇总”的小闭环。
3. **把研究规则写出来**：形成岗位族定义、纳入排除规则、数据字典、编码手册和 prompt 的 v0.1。
4. **把项目基础设施搭好**：建立共享目录、版本命名、任务看板、复核记录和问题清单。

假期结束时，团队不一定要有大量数据，但应该能够拿出一个可演示的最小成果：

> 10–20 条公开招聘文本 + 人工标准答案 + 一版 LLM 结构化抽取结果 + 人工复核记录 + 一页方法说明。

这比单纯读很多论文更有价值，也比直接采集几百条数据更稳妥。

---

## 二、假期期间可以独立完成的任务

### P0：必须完成

#### 任务 1：全员建立共同概念

每个人都要能用自己的话解释以下概念，不追求背定义：

- 招聘广告不等于真实职位空缺；
- 非结构化文本如何转成结构化变量；
- 关键词/词典法、传统文本分析和 LLM 提取分别有什么优缺点；
- prompt、zero-shot、few-shot、结构化 JSON 输出是什么；
- 幻觉、漏提、错分和口径漂移是什么；
- 为什么要人工标准答案、双人编码和人工抽查；
- 什么是准确率、召回率、F1 和编码者一致率；
- 招聘数据为什么存在平台偏差、重复发布和选择性披露。

**交付物**：每人一页学习卡片，最后合并成《方法概念速查表》。

#### 任务 2：精读少量核心材料，而不是泛读很多材料

建议按下面顺序读：

1. BIS《Large language models: a primer for economists》：全员重点读数据组织、信息提取、评估部分。
2. 《大语言模型与经济金融文本分析：基本原理、应用场景与研究展望》：陈鑫垚精读，全员浏览。
3. ACM《Extracting Structured Labor Market Information from Job Postings with Generative AI》：梁夏伟主读方法和 prompt，全员看研究流程。
4. Gentzkow、Kelly、Taddy《Text as Data》：陈鑫垚重点整理“文本如何成为经济学变量”。
5. Deming & Kahn《Skill Requirements across Firms and Labor Markets》：张庆阳重点整理岗位—技能分析框架。

不要把任务做成“每个人读完写读书笔记”。每篇材料只回答五个问题：

- 研究对象是什么？
- 原始文本如何变成变量？
- 人工或模型如何判断提取得对不对？
- 数据有什么偏差？
- 哪一条做法可以借到我们的课题？

**交付物**：《文献方法对照表》，每篇 1 页以内。

#### 任务 3：用 10–20 条真实岗位做人工编码

先不要让 AI 处理。选取能代表不同情况的岗位：

- 至少覆盖 4 类岗位族；
- 包含描述完整、描述很短、边界模糊和技能组合复杂的岗位；
- 尽量保留来源网址、采集日期和原文；
- 不复制和保存个人电话、邮箱等无关联系方式。

至少两名成员对同一批岗位独立编码，判断：

- 是否纳入研究；
- 岗位族；
- 学历要求；
- 专业要求；
- 经验要求；
- 技术技能词；
- 软技能词；
- 每个技能词在原文中的证据句；
- 描述质量等级；
- 无法判断的地方和理由。

**交付物**：《标准答案集 v0.1》+《人工编码分歧记录 v0.1》。

#### 任务 4：跑通一次 LLM 小样本提取

用同一批岗位中的 5–10 条进行试跑。LLM 只做信息提取和候选归类，不直接决定最终分类。

Prompt 至少要包含：

- 只能依据原文；
- 原文没有的信息填 null，不得按岗位名称推测；
- 技能词尽量保留原文表述；
- 每个技能词必须给出支持它的原文句子；
- 严格按照固定 JSON 输出；
- 岗位族不确定时返回“待复核”；
- 不要把公司名称或岗位名称自动当成技能。

人工逐条对照模型结果，记录：

- 漏提了什么；
- 编造了什么；
- 哪些技能被拆分过度或合并错误；
- JSON 是否完整；
- 哪类文本最容易出错。

**交付物**：`prompt_v0.1`、5–10 条模型结果、错误记录和修改建议。

### P1：有时间再完成

#### 任务 5：建立六类岗位族的边界表

六类岗位族暂按以下名称建立初版：人工智能、数据分析、软件开发、智能制造、数字营销、产品运营。

每类至少写出：

| 内容 | 要求 |
|---|---|
| 定义 | 这类岗位主要完成什么任务 |
| 正例 | 至少 3 个岗位标题或文本例子 |
| 反例 | 看起来相近但不纳入的例子 |
| 边界例 | 需要讨论的混合岗位 |
| 关键词 | 检索和初筛用，不等于最终分类 |
| 最终判断依据 | 看岗位任务和技能要求，不只看标题 |

重点处理这些容易混淆的情况：

- “数据运营”是否属于数据分析还是产品运营；
- “算法工程师”和“软件开发”如何区分；
- “自动化工程师”是否纳入智能制造；
- “电商运营”在什么条件下属于数字营销；
- 同一岗位同时涉及多类能力时，是主分类还是多标签。

这个问题暂时可以形成团队内部规则，但正式锁定前留在“待老师确认清单”里。

#### 任务 6：把能力框架从“六个大类”细化成三级编码

建议先用三级结构：

```text
能力簇 → 能力项 → 技能词/任务
```

初版能力簇可以继续沿用：

1. 技术与工程实现；
2. 数据处理与分析；
3. 业务与产业理解；
4. 数字工具与运营；
5. 项目实践与问题解决；
6. 协作沟通与职业素养。

每个能力项都要能回答：

- 招聘文本中什么表达可以证明它出现？
- 学生问卷中准备如何测量它？
- 它和相邻能力项如何区分？

例如：

| 能力簇 | 能力项 | 招聘文本证据 | 学生端可能的测量 |
|---|---|---|---|
| 数据处理与分析 | 数据清洗 | “负责清洗、整理业务数据” | 是否能独立完成一份给定数据的清洗任务 |
| 数据处理与分析 | SQL | “熟练使用 SQL 查询数据库” | 能否独立写出基础查询 |
| 技术与工程实现 | 软件开发 | “负责后端系统开发与维护” | 是否完成过可运行的软件项目 |
| 项目实践与问题解决 | 项目实践 | “有相关项目或实习经验优先” | 是否有项目、实习或竞赛经历 |

不要在假期内追求非常精细。先让每个人能用同一规则给岗位编码即可。

#### 任务 7：学习招聘数据的获取、清洗和去重

至少理解并练习以下流程：

```text
确定抽样框
→ 记录来源和采集日期
→ 保留原文与元数据
→ 去重
→ 判断纳入/排除
→ 字段标准化
→ 描述质量分级
→ 人工编码
→ LLM 候选提取
→ 人工复核
```

需要特别理解：

- 同一职位可能在多个平台重复发布；
- 同一企业可能长期刷新同一职位；
- 招聘广告的条数不能直接解释为岗位数量；
- 职位描述过短时，只能用于有限的结构统计；
- 关键词命中只能做候选筛选，不能替代人工复核；
- 每条数据必须能回到来源网址、原文和采集批次。

假期期间只使用已经确认公开且不需要登录的来源，或使用已有的技术验证数据；不要尝试商业平台自动抓取，不要绕过验证码、登录或访问限制。

#### 任务 8：学会 Excel 和基础 Python 的最低必要操作

不要求现在学会机器学习，也不要求训练模型。只练项目马上会用到的内容：

**Excel：**

- 筛选、排序、冻结表头；
- 去重和重复标记；
- 文本长度统计；
- 缺失值检查；
- 数据透视表；
- COUNTIF、COUNTIFS、XLOOKUP 或同类查找函数；
- 由岗位族 × 能力簇生成出现次数和出现率表。

**Python：**

- 读取和写出 CSV/XLSX；
- 统计行数、缺失值和重复值；
- 规范化空格、大小写和标点；
- 按岗位族分组统计；
- 保存运行日志；
- 读懂已有采集框架的配置、输入和输出。

每个人至少独立完成一个小练习，不能只让会 Python 的成员负责全部操作。

## 四、假期结束时的验收标准

满足以下 8 项，就说明项目正式开始前的准备基本合格：

- [ ] 每个人能解释招聘广告与真实职位空缺的区别；
- [ ] 每个人能拿一条原文，指出其中至少 3 个可提取变量；
- [ ] 团队有一份保留原文和来源的 10–20 条岗位小样本；
- [ ] 两名成员完成同一批岗位的独立编码；
- [ ] 分歧被记录，并形成至少 10 条编码规则；
- [ ] LLM 能对 5–10 条文本输出固定格式结果；
- [ ] 团队能指出模型至少一种漏提风险和一种幻觉风险；
- [ ] 能从一张底表生成一个“岗位族 × 能力簇”的简单统计表。

如果这 8 项都完成，老师回来后讨论的就不是“你们准备做什么”，而是“这套初版规则如何调整、哪些渠道可以正式使用”。

## 五、假期期间明确不要做的事

1. 不要直接把苏高新人才网的 255 条技术验证快照当正式研究样本。
2. 不要在老师未确认前承诺 600–1000 条岗位、250–400 份问卷等硬目标。
3. 不要先做网页仪表盘；静态表、矩阵和过程留痕优先。
4. 不要让 LLM 直接替代岗位族最终判断或能力编码。
5. 不要只统计关键词频数；每个重要结论必须能回到岗位原文。
6. 不要为了练习而批量抓取商业招聘平台。
7. 不要在没有人工标准答案的情况下直接批量跑模型。
8. 不要四个人各自使用不同规则，最后再尝试拼接结果。

## 六、老师回来后集中确认的问题

假期期间把问题记录好，不必反复打扰老师；开学后一次性确认：

1. 六类岗位族是否必须全部分别分析？样本不足时能否合并或改做案例？
2. 岗位族采用单一主分类还是允许一条岗位有多个标签？
3. “高新区及周边”的具体地域边界是什么？
4. 苏高新人才网是否允许按现有公开访问方式进行有限度采集？
5. 是否推荐申请 CnOpenData 线上招聘数据试用？学院是否有自购数据资源？
6. 能力框架是否可以参考 O*NET/ESCO，再按中国语境调整？
7. 企业需求与学生能力的匹配矩阵，老师更认可哪种标准化和差距计算方法？
8. 学生问卷应覆盖哪些高校、专业、年级，是否有最低样本要求？
9. 研究中使用网页版模型是否合适，是否需要统一模型、记录模型版本和 prompt？
10. 初审前需要达到什么数据量和分析深度？

## 七、建议团队下一次会议只讨论四件事

1. 从哪 10–20 条岗位开始试编码；
2. 哪两个人做独立编码，其他人如何复核；
3. 共享文件夹和文件命名规则；
4. 假期结束前各自交什么，交付日期是什么。

会议不需要讨论“最终报告写得多漂亮”，也不需要讨论“网页要做成什么样”。当前最重要的是让一条真实数据完整走通，并留下能够复核的过程记录。
